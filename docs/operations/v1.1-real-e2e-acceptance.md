### Run 1: Primary Happy Path
- **Target Role:** Graduate Backend Software Engineer- UpNEXT Program
- **Company:** Next Insurance
- **Location:** Kfar Saba, Israel (hybrid)
- **ATS Platform:** Greenhouse (`https://job-boards.greenhouse.io/nextinsurance66/jobs/7979131003`)
- **Outcome:** Complete end-to-end traversal across all 5 review stages:
  1. Discovery & Hydration via Greenhouse API
  2. Candidate fit evaluated against `config/profile.yml` & `cv.md` (0 YOE, GPA 85)
  3. Tailored CV generation & PDF validation
  4. `PRE_SUBMIT_REVIEW` notification delivered to Telegram -> Human decision: `PREPARE_APPLICATION`
  5. Read-only form schema extraction & field mapping -> `ATS_PREPARATION_REVIEW` -> Human decision: `FILL_APPLICATION`
  6. Controlled safe fixture fill -> `FINAL_HUMAN_REVIEW` -> Human decision: `CONTINUE_MANUALLY`
  7. Automation halts; human submits manually on employer website
  8. Human confirms submission via Telegram: `/confirm_submission <app-id>`
  9. Tracking and timeline update to `APPLIED_CONFIRMED`
- **Result:** **PASS**

## Telegram Threat Model Audit (PART D)

All 20 threat model scenarios passed automated verification in `tests/agent/telegram-threat-model.test.mjs`:
1. **Unauthorized User:** Updates from unauthorized `from.id` rejected with fail-closed 403.
2. **Unauthorized Chat:** Updates from unauthorized `chat.id` rejected.
3. **Forged Callback Token:** Random or forged token IDs rejected with `FORGED_CALLBACK_TOKEN`.
4. **Stale Callback:** Callback for previous application state rejected with `CANONICAL_STATE_MISMATCH`.
5. **Cross-Application Binding:** Callback bound to App A rejected when attempted on App B.
6. **Task Binding Mismatch:** Callback with mismatched `review_task_id` rejected.
7. **Evidence Change:** Callback rejected if review evidence hash has changed.
8. **Duplicate Callback:** Idempotent response without duplicate receipt generation.
9. **Conflicting Decision:** Reject second conflicting decision on decided review.
10. **Replayed Update ID:** Telegram long polling deduplicates processed `update_id`s.
11. **Malformed Payload:** Handled safely without polling crash.
12. **Oversized Text:** Bounded to 4096 characters, preventing buffer/memory issues.
13. **Prompt Injection in Telegram Message:** Treated strictly as untrusted data, never as instructions.
14. **Prompt Injection in JD:** Fenced by evaluator and candidate-fit policy.
15. **Command-like Text:** Safe fallback help response; zero shell or JS execution.
16. **Token Leakage:** Bot tokens sanitized to `<REDACTED>` in all logs, URLs, and errors.
17. **Network Timeout:** Bounded AbortSignal timeout with retryable classification.
18. **Telegram 429:** Bounded backoff respecting `retry_after`.
19. **Telegram 5xx:** Bounded exponential backoff.
20. **Crash Before Local Ack:** Delivery store reconciliation prevents duplicate messages.
